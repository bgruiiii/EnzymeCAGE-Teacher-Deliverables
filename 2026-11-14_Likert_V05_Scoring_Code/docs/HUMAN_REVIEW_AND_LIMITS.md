# NE、HELD与人工复核的真实边界

## 已完成的内容

本地存在实际执行过的AI辅助评分代码与原通信记录，不是只有rubric文档。最后已有706个评分位置可计算总分；本目录仅公开源码、规则、合成示例和计数摘要，不公开原始答卷/Gold/通信。

历史S6全量完整输出协议和S8后续局部协议都保留。S8修的是自动未知被整维挂起、分支主链范围未接入、无歧义表达被拒等执行问题；后续评价侧补证另标证据版本，不把新旧输入都说成同一份从未变动的冻结材料。

## 复核标记不是已发生的人评

- `NE`：该维暂不可判，score=null；不会自动变成0、低分或重新归一化总分。
- `MISSING`：答卷未交付该模块，score=1；不是API失败。
- `HELD/REVIEW_PENDING`：程序或结果中的暂停／待审状态，不代表真人已经接单、审核或批准。
- `review_flags`：机器可读复核事项。代码没有一个已上线的服务自动完成双人人评。

有些旧NE来自程序/Prompt冲突而非真正科学不可判；这类后续已定向修复。真正的身份、能力、性状、来源缺口须有实际材料才能判断，不能仅为消NE编出整数。

## 校准与外部效度

之前32份是AI评分流程校准及技术/规则痛点检查，不能说成两名生物背景专家独立评分。历史混合一致性、人类评分和AI评分要分列；当前没有依据宣称双人独立外部效度已经完成。

人工外部效度是独立的评分轨，对同一冻结答卷/量表给出真实人分、评价者身份及暴露声明，再作原始一致性/分歧分析；它不是AI调用中的一个已经自动运行的节点。

0012的范围理由复审标记仍保留。某些“有数值”结果也可能待专家科学复核，因此706/706可算总分不能写成706份科学正确性都被确认，更不能说微生物培养/蛋白催化实验已验证。

## 本次代码整理不等于新实验

此目录的15项单元测试和离线示例证明接口、范围/引用/身份门、总分、修复不覆盖旧数值、unknown保留等实现行为；它们不证明科学效度。本次未调用评分API、未生成新实验结果，也未改变depending的在线图。
