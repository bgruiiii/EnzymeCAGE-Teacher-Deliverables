## 一、路线模式（问 1）：批准，补自由路线约束

主实验 = 指定路线，唯一计分口径。自由路线允许作为探索实验，约束三条：

1. 单独建实验、单独报告，**不与主实验混分、不进五模型排名**；
2. 自由路线的「路线有效性」判定必须有确定性锚（本地库路线等价类/白名单），不允许评测人纯人工拍板「这条路线也算对」；
3. 自由路线题面与主实验题面**分开生成、分开冻结**，防止题面措辞互相污染。

## 二、评分权重（问 2）：裁定如下，不开放再议

科学分 100% 内部分层：

| 层 | 内容 | 权重 |
|---|---|---|
| 路径层 | 主底物名称、主产物名称、步骤匹配/漏步/多步/顺序/断链 | **45%** |
| SMILES 层 | SMILES 合法性 + 结构正确性（与 gold canonical 匹配） | **10%** |
| 酶层 | 酶名称/功能、EC、酶-微生物配对 | **20%** |
| 微生物身份层 | 物种/菌株/NCBI TaxID/genome accession/保藏编号 | **15%** |
| 性状层 | 15 项性状完整率 + observed-gold 准确率 | **10%** |

**证据轴独立**：证据覆盖率/可核验率/支持正确率单独成轴报告，不进科学分加权。处置规则：

- 答案正确且证据可核验 → `verified_correct`（唯一可对外引用口径）；
- 答案正确但证据不可核验/缺失 → `unverified_correct`，科学分保留但报告分层呈现；
- 证据错误（record_id 查无、claim_scope 与字段不符）→ 计**幻觉记录**，按模型汇总披露。

**工程指标独立**：JSON 有效率、截断率、耗时、token、cost 出独立工程报告，不进科学分。

**敏感性分析义务**：最终报告附「权重 ±5pp 扰动下五模型排名稳定性」一节，证明结论不依赖具体权重取值。

## 三、矛盾 case 处置（问 3）：quarantine 子集

1. S4-R2 后仍有真实 cycle 或数据矛盾的 case **一律不进正式计分题库**；
2. 建 quarantine 清单（case_id + 矛盾描述 + 剔除日期 + 处置人），随报告披露剔除率与原因分布；
3. 剔除后不足 150 条：优先补选（走同一选择流程），无法补选则降额并在报告首页披露最终 n；
4. quarantine 子集可单独跑五模型（同管线），作为「gold 不确定性下的模型行为」观察材料，单独成节，不进主排名。

## 四、enable_search（问 4）：有条件批准，对称性探针前置

批准「统一 enable_search=true、不评价搜索行为、metadata 只落盘」作为产品模式口径，**前提**：

1. smoke 之前加跑 **search-efficacy 探针**：每模型 2–3 条带时效性答案的探针题，程序检查返回 metadata 中是否真实含检索记录；
2. 五模型全部探针通过 → 主实验按 enable_search=true 执行；
3. 任一模型探针失败（网关静默忽略/不支持）→ **主实验统一改 enable_search=false**，搜索开启版整体降级为探索实验单独报告。不允许「部分模型真搜、部分不搜」的混合状态进入主实验；
4. 报告必须披露各模型搜索实际生效状态与 metadata 返回率；报告全文不得出现任何「联网能力」暗示性表述。

理由：主实验是能力评测，输入信息条件必须对称。「不评价搜索」解决的是评分口径，解决不了输入不对称对科学分的污染。

## 五、性状分母与 F5（问 5）：确认 observed-gold，补防编造

1. 确认 §7.3/§10 口径：准确率分母 = 本地 gold/性状表有值的字段；完整率分母 = 全字段；**两率分开报**，不得合并成单一「性状得分」；
2. F5 保藏编号：gold 有值时精确匹配计分；gold 无值时模型返回不进分母，**但**返回编号格式非法或在本地保藏表查无此号 → 计幻觉记录（「不能预测」的含义是「不许编」，不是「随便写不扣分」）；
3. 温度/pH/盐度的 min/optimum/max 子字段：逐子字段计缺失，以 optimum 为主口径；**精确匹配 gold 记录值，不设容差**（容差引入评测人主观性；区间重叠问题留报告讨论节）；raw_text 不参与评分，只做审计抽查材料。

## 六、smoke/pilot（问 6）：批准，升级为硬门

1. **smoke 门**：5 模型 × 3 题，JSON 有效率 15/15 才进 pilot；任一模型失败 → 修 schema/prompt/参数后重跑 smoke（重跑只计工程，不进正式分）；
2. **pilot 门**：5 × 10 题，四项全过才进全量：
   - JSON 有效率 ≥ 49/50；
   - 截断率（finish_reason=length 或 visible content 为空）≤ 10%，超过则提 max_output_tokens 或精简字段后重 pilot——注意 reasoning 模型的 max_output_tokens 是「思考+输出」总预算（T6 教训：kimi-k3 选菌层 4000 token 被 reasoning_content 吃光致 7 例 fail-closed），16384 对 15 步长 JSON 是否够，由 pilot 数据说话；
   - 单 case token/耗时分布出炉 → 定全量并发与**预算估算，报老师确认后**才启动全量；
   - 每模型抽 2 题人工审计答案形态正常（无空 JSON、无全 null 糊弄、无题面复读）；
3. **smoke/pilot 数据不进正式评分**。全量阶段 150 题用最终冻结参数**全覆盖重跑**（smoke/pilot 题也在内），保证 750 次正式调用口径绝对统一。多出的 65 次调用成本接受。

## 七、JSON 结构与配对规则（问 7）：批准结构，补 4 条评分规则

结构（schema_v1、顶层字段、steps/organism_profiles 去重引用、evidence_registry）批准。「每步一个首选酶-菌配对」作为题目形态保留——它就是对模型证据纪律的压力测试。补：

1. **步骤对齐算法先于跑分冻结**：建议按「底物∪产物 compound 集合」做二分图对齐（名称走 gold 同义词表），对齐后才有漏步/多步/顺序/断链的可复算定义；算法代码随评分器冻结，禁止跑完看结果再调；
2. **超链步骤处置**：模型把主链终点后的延伸步骤放进 `downstream_continuation` → 不罚（这正是主链主张 vs 下游推测的分层，与 9-18 架构裁决的终点分级哲学一致）；混入 `steps` → 按多步错误计；
3. **证据程序校验**：`DATABASE_DIRECT` 的 record_id 必须能在本地库 lookup（如 `BSY-r00220` ∈ Reactions 表），lookup 失败直接计证据幻觉；`MODEL_INFERENCE`/`INTERNAL_KNOWLEDGE_ONLY` 不进可核验分，但**按模型统计占比**——这是五模型诚实度的关键对比维度；校验脚本作为评分器一部分同步冻结；
4. **SMILES 口径**：合法性用 RDKit 程序判定；结构正确性主口径 = isomeric SMILES 匹配（区分立体），另报去立体口径作参考；gold 侧 canonicalization 用同一 RDKit 版本，版本号入报告。

另补一条评分哲学：**诚实弃权区别于编造**。recall（gold 有值且答对）与 overclaim（答了但错 + 高置信且证据不可核验）分开统计；模型 null 在 recall 计 miss，但**不进 overclaim**——null 必须比「编一个错答案」得分好，否则评测在激励幻觉。

## 八、遗漏补充（设计稿未覆盖，均为硬要求）

1. **一次科学回答的程序强制**：每 case 请求体 hash 去重落盘；仅网络失败/429/5xx/超时可原请求重试；每次 attempt（含重试）全量记录；JSON 解析失败不得重问（已有，确认程序实现而非自觉）。
2. **评分器先冻结后见输出**：评分脚本定稿 + 用 3 个手工构造 mock 答案（全对/全错/部分对）自验输出符合预期 → 冻结 hash → 之后才允许对真实模型输出跑分。评分器任何后续修改，已出分数全部作废重算。
3. **题面泄漏程序检查**：题面生成后程序校验不含 gold 字段值（酶名/EC/步数/数据库 ID/SMILES/终产物名的 grep 级检查），并保存题面版本 hash；抽 10% 老师侧人工审计中文名→污染物指向唯一性。
4. **模型版本与参数漂移**：记录每次调用的模型版本标识/system_fingerprint（若网关返回）；全量 750 次压缩在尽可能短的时间窗内完成；per-model 实际生效参数表（temperature 实际值、max_output_tokens、被网关忽略的参数清单）随报告发布。
5. **预算上限**：pilot 后按实测 token 分布给出 750 次成本估算，老师确认前不得启动全量。
6. **同污染物多分支的 gold 隔离**：150 case 非同 150 个污染物（设计稿已声明），评分器须按 case_id 取 gold，禁止按根污染物合并——防止 A 分支步骤被算进 B 分支 gold。
7. **JSON 解析口径**：先 `json.loads`，仅允许剥一层 fenced code block，失败标 `INVALID_JSON`（已有，批准）；schema 校验用 strict 必需字段 + 额外字段记 warning 不 fail。

## 九、流程硬门（顺序不可跳，任何 gold 变更则已跑数据作废）

```
S4-R2 独立审计通过
  → gold 冻结（hash 锁定，hidden gold + trait gold 分别落 hash）
  → 150 题面生成 + 泄漏程序检查 + 10% 人工抽审
  → 评分器冻结 + mock 三例自验
  → search-efficacy 对称性探针（决定 enable_search 最终口径）
  → 3 题 smoke（门：JSON 15/15）
  → 10 题 pilot（门：有效率/截断率/预算确认/人工抽审）
  → 750 次全量（统一冻结参数，全覆盖重跑）
  → 本地评分（冻结评分器）→ 五模型报告
```

## 十、定位声明（写入最终报告引言）

本评测是**五个通用大模型 API 的裸能力基线**（一次性端到端回答 + 证据完整性），不测 EnzymeCAGE 排序模型、不测编排系统。其分值不得与 EnzymeCrew「确定性骨架 + LLM 节点」全链路输出直接对比；正确的用法是作为对照组，量化「裸 LLM vs 编排+检索+冻结模型」的差距方向与量级。
