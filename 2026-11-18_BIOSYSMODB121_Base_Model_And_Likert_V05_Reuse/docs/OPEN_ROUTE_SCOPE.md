# 不限路线时，现有V0.5的适用边界

本文说明已有资产的条件，不给师兄规定20题怎么选、怎么问或必须得出什么结论。

## 可以直接复用

- 七维名称、权重、评分档位与证据/缺失规则：D1/D2/D3a/D3b/D4/D5/D6，权重15/25/10/10/15/15/10。
- 请求与回包协议、真实模型/身份/引用/范围校验、总分公式、归档、去重。
- 原121题、原输出字段、Gold/accepted与参考来源，作为已有路线的参考资产。
- 既有原答与评分样例，用于核代码，不作为新答案的预定分数。

## 必须与新任务相符的输入

| 原实现的条件 | 不限路线后要注意 |
|---|---|
| 题面明确指定路线/氧条件 | 没给这些条件，就不能以“没走旧路线/换了旧氧条件”直接触发D1任务违约 |
| D3a目标反应是已给任务主链 | 新答案选择的路线是否在评价目标内、能对应哪套Gold，须明确；不能只核其内部酶自洽，也不能拿不相关旧路线硬套 |
| 原Gold覆盖某条路线 | 不是该污染物所有有效路线的穷举；Gold未命中不能自动认定反应或酶错误 |
| 旧CTX、ART、STEP_ALIGNMENT、KEY失败证明 | 绑定旧答案SHA/题面/目标，不能换成新答案继续消费旧事实和封顶 |
| 旧BASE_RANGES/自动NE出口 | 已有S8修复不能被旧包装重新带回；真正关键参考缺口仍可能NE |
| 字段格式 | 若新答案形状变化，可无歧义转换字段并留映射，不能重写科学内容或借转换填缺项 |

原scope的作用是让评分程序知道在评什么。任务变了，应提供反映新题面和参考覆盖的事实合同；不能通过删掉校验、统一填4、把区间一律设1–10来假装问题解决。

## 如何区分“不能评分”的原因

- **调用/工程问题**：端点、模型参数、流解析、JSON或字段类型；它们与量表科学适用性不是同一问题。
- **旧任务合同误接**：题面已不限制路线，程序还沿旧Gold路线扣任务偏离。这是输入/接线问题，不能归因于新模型答错。
- **参考覆盖不足**：模型给了另一条可能有效路线，现有Gold/证据不能确认。应明确缺什么，不能把不在旧表里当已证伪。
- **可以有据评价**：现有参考与新任务确有对应、材料足以判断，按现有档位给分；不因某个次要未知把整维挂起。

本包不提供“所有污染物任意路线都能自动科学评分”的承诺。评分调用成功只说明工具链能工作，公平适用性还取决于范围和证据。

## 参考材料在哪里

`reference/gold_121/`是现有程序参考表，带060/094已采用范围修正；`original_task_contracts/`是原指定路线合同/accepted/主链目录，`case_overrides/`记录补充来源。016只要求原来至p-cumate的前三步，其他背景不当必答；060/094当前参考由用户决定，不冒称专家签署。

accepted登记与原Gold不一定覆盖全部121题的所有酶与新路线；空切片不是“无正确答案”。不同污染物题目可能共用同一底物或分支，case_id仍是旧参考关联键，不能因新输入相同就静默混合多个旧答案库。

真实原任务样例`examples/real_original_task/`只用来验证原输入的可复算性；新题面/新答案必须重新构造事实与请求身份，不能拿该样例换正文后沿用其上下界。
